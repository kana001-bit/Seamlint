# Seamlint Vision

この文書は、Seamlint が最終的にどこを目指すかを描く。
出発点の動機は [`why.md`](why.md)、用語の定義は [`core-concepts.md`](core-concepts.md)、
責務境界とデータモデルは[`architecture.md`](architecture.md) を参照。
ここでは将来の到達像に絞る。

Seamlint は、型紙の幾何を **正直に測る** ことだけを引き受ける小さな道具である。
本格的な CAD は置き換えない。
型紙作成や幾何編集は Valentina などの外部 CAD に任せ、
Seamlint は「その形が縫い合うか」を早く・説明可能に・正直に測ることに徹する。

## 目指すもの

Seamlint が支援したいのは、布を裁つ前の次のような確認である。

- 明らかに長さの合わない seam を先に見つける
- 閉じるはずが開いている輪郭を見つける
- 滑らかに続くべき所が角になっているのを見つける
- ease / gather / band の和が想定の範囲かを測る
- そして、測れない入力を静かに通さず「測れない」と言う

目指すのは、全部に合格する型紙ではなく、幾何の食い違いを **早く・説明可能に・正直に**見つけられる状態である。

## 測るだけの道具であり続ける

Seamlint の価値は「測るだけ」という狭さにある。読み取り専用で、型紙を勝手に触らない。
対応点（notch）も推定せず、人か上流（Loomit）が宣言する。

将来チェックの種類が増えても、この境界は動かさない。
CAD 編集や auto-fix を混ぜた瞬間、read-only の保証が崩れ、誤修正が物理工程に流れる。
測定と修正を分けておくことが、下流がSeamlint の数値を信頼できる理由であり続ける。

## いちばん怖いのは、静かに間違えること

計測値は布を裁つ・縫う工程へ流れる。
だから Seamlint のいちばん重い失敗は、クラッシュではなく **自信ありげに間違った数値を返すこと** である。
測れないもの（`transform` / 非等倍`viewBox` / 未対応コマンド / 点不足）は測ったふりをせず `error` で止める — この原則は、機能が増えても最優先で守る。

## measure → fix のパイプライン

Seamlint は測るところまでを持ち、直すのは持たない。
見つけた問題を人の承認のぶんだけ実際に補正するのは、将来の **Truer**（linter に対する formatter の位置づけ）に残す。
そして「どの辺とどの辺が縫い合うか」という宣言は **Loomit** が持つ。

- **Loomit** — プロジェクトの構造とグラフ（宣言レイヤ）
- **Seamlint** — 幾何の測定（この道具）
- **Truer** — 承認された補正の適用

この 3 者が、同じ狭い契約（`GeometryCheckRequest` / 構造辺の住所）でつながる形を目指す。

## 標準フォーマットに乗る

測定の主ソースは ASTM DXF に寄せる。ASTM は標準なので、layer の意味（縫い線 = `layer 14`など）を、ファイル固有の当て推量ではなく標準に基づいて確定できる。
SVG は限定的な対応として残す。
将来 notch が export されるようになれば、gather / ease の range チェックもフルに動く。

## standalone でも library でも使える

Seamlint は Loomit 専用の付属品ではない。
`slnt` CLI 単体でも、ローカル Node package のAPI としても使える。
上流が Loomit でなくても、SVG / DXF の座標列さえ渡せば測れる形を保つ。

## MVP を、必要になったら本物に置き換える

現在の parser・sampler・ベクトル計算は、依存を増やさないための最小実装である。
壊れやすい MVP（regex parser / 自前 length）を、`svg-pathdata` / `svg-path-properties` /
`bezier-js` のような scope の明確な library で **置き換える** 価値が出たときに差し替える。
測定エンジンは入力形式に依存しないので、parser を替えても測定側は動く。

## 段階的に育てる

Seamlint の価値は、最初から大きな統合ツールになることではない。
型紙の作業ディレクトリに自然に入り、`slnt check` で安心できることから始める。
チェックの種類・フォーマット対応・library 置き換えは、実データで必要になった順に足す。
