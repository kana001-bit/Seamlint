# Why Seamlint Exists

この文書は、Seamlint の仕様や設計史ではなく、「なぜ幾何を測る道具を別に切り出したのか」を残すためのメモである。

服作りの困りごとそのものは、姉妹 project の Loomit の
[`why.md`](https://github.com/kana001-bit/Loomit/blob/main/docs/why.md) に書いてある（問題が
見つかるのが遅い、途中の判断を残したい、洋裁にソフトウェア的な道具立てを持ち込みたい）。
Seamlint はその中の **幾何の測定** だけを引き受けるために生まれた。
ここでは「なぜ測定を分けたか」を書く。

## 「合うか」は、宣言ラベルでは分からない

型紙の 2 辺が縫い合わさるかは、最終的に **仕上がり線の弧長** の問題である。

- 袖ぐりと袖山は、宣言された `length_mm` が近いことではなく、実際の曲線の長さが揃うことで合う。
- connector の id が同名だから繋がる、というのは宣言ラベルであって、幾何ではない。
- 「滑らかに続く」「ちゃんとわっかに閉じる」も、目で見た印象ではなく座標で測れる性質である。

Loomit は project の構造とグラフ（宣言レイヤ）を持つが、幾何は計算しないと決めた。
すると「宣言が実際の形と合っているか」を測る役が要る。それが Seamlint である。

## `.val` を評価するのは重い。SVG / DXF なら測れる

仕上がり線の長さは `.val`（Valentina のパラメトリックモデル）に数値としては実在しない。
点の数式・寸法参照・曲線を評価して初めて出る **計算値** である。
「正本は `.val` だから読めば取れるはず」は精神としては正しいが、実務としては読取り射影ではなく幾何計算が要る。

Seamlint は `.val` を再実装しない。代わりに、書き出された SVG / DXF の **座標列** を測る。
これは「CAD エンジンを作らない」という Loomit 側の判断（A案）と地続きで、Seamlint は測定だけに徹する。

## 静かに間違えない道具

計測値は最終的に布を裁つ・縫う物理工程へ流れる。
だから Seamlint のいちばん重い失敗はクラッシュではなく、**自信ありげに間違った数値を返すこと** である。

- 単位や座標系が前提と違うのに `mm` と言い切る
- 未対応の command を黙って飛ばして測る
- サンプリングが粗くて、同長の seam を mismatch と誤検出する

こうした silent な誤りは、下流（Loomit / CI / 裁断）が気づけない。
Seamlint は、測れないもの（transform・非等倍 viewBox・未対応 command・点不足）を「測ったふり」せず、
明示的な `error` で止めることを最初から設計に入れている。

## 直さない。測って、人に返す

Seamlint は read-only である。型紙を勝手に触らない。

- `check` はファイルを書かない。lint に auto-fix を混ぜない。
- 対応点（notch）は人が宣言する。Seamlint は推定しない。
- 最終的なミリ単位の補正と CAD 書き込みは、将来の Truer の担当に残す。

この「測るだけ」という狭さが、Seamlint の信頼の土台である。
CAD 編集を混ぜた瞬間、read-only の保証が崩れ、誤修正が物理工程に流れてしまう。

## 目指しているのは、試作をなくすことではない

Seamlint は試作を不要にする魔法ではない。布の伸び・着心地・見た目のよさは、測ってもわからない。

それでも、試作の前にできることはある。

- 明らかに長さの合わない seam を先に見つける
- 閉じるはずが開いている輪郭を見つける
- 滑らかに続くべき所が角になっているのを見つける
- 測れない入力を、静かに通さずに「測れない」と言う

Seamlint が目指すのは、幾何の食い違いを **早く・説明可能に・正直に** 見つけることである。
