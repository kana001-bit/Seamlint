# Seamlint 設計史 (Design History)

この文書は、Seamlint の設計がどう育ってきたかを残すための記録である。

残したいのは「最初から正しかった設計」の一覧ではない。どこで詰まったか、何を思い込んで
訂正したか、何を捨てて何を残したか — 測るだけの小さな道具が、どういう壁にぶつかって今の形に
なったかを、後から読み返せるようにしたい。

## 「合うか」は、宣言では分からなかった

Seamlint は、姉妹プロジェクトの Loomit から幾何の測定だけを引き受けるために生まれた。

Loomit は服作りを Git のように扱う道具で、型紙の構造とグラフ(宣言レイヤ)は持つが、
幾何は自分で計算しないと決めていた(CAD エンジンは作らない、という方針)。
ところが「この 2 辺は縫い合わさるのか」は、connector の id が同名だとか、`length_mm` にこう書いたとか、宣言では決まらない。
最終的には**仕上がり線の弧長が揃うか**という、座標を測って初めて言えることだった。

袖ぐりと袖山が合うのは、宣言された長さが近いからではなく、実際の曲線の長さが揃うから。
「滑らかに続く」「ちゃんとわっかに閉じる」も、目の印象ではなく座標で測れる性質だった。

だから宣言レイヤ(Loomit)と測定レイヤ(Seamlint)を割った。
Seamlint はその測定だけを、狭く引き受ける。

## いちばん怖いのは、静かに間違えること

作り始めてすぐ、この道具の性格が決まった。

Seamlint が返す数値は、最終的に**布を裁ち、縫う物理工程へ流れる**。
10 倍ずれた寸法が warningすら出さずに通れば、下流(Loomit / CI / 裁断)は気づけない。
つまりこの道具のいちばん重い失敗は、クラッシュではなく、**自信ありげに間違った数値を返すこと**だった。

そこで最初から一本の背骨を通した — **測れないものは、測ったふりをしない**。
単位や座標系が前提と違う、未対応のコマンドがある、点が足りない。
そういうときは黙って測らず、明示的な `error` で止める。
方針を一言でいえば「黙って測るより、測れないと言え」。

同じ理由で、Seamlint は読み取り専用に徹して、勝手には直さない。
対応点(notch)も人が宣言し、Seamlint は推定しない。
この「測るだけ」という狭さが、信頼の土台になった。
これから出てくる判断は、ほとんどがこの背骨を守るためのものだ。

## SVG で詰まった

最初は、Valentina が書き出す **SVG** を測るつもりだった。
SVG は描画結果そのものだから、形を測るだけなら十分だろうと考えていた。

ところが実際の `waist.svg` を調べると、必要な手がかりが思ったより失われていた。
72 個の path はどれも id が無く、detail 名も無く、notch も無い。
おまけに 1 描画単位が 1mm ではなく約 0.264mmという非等倍で、全部の path が親グループの座標変換(`transform`)を被っていた。

SVG は「形」は持っていても、「**どの辺がどのパーツのどの縫い目か**」という手がかり(identity)を持っていなかった。
valentina側の操作で配置用の書き出し(layout export)に替えても、identity はゼロのまま。
描画としては正しくても、測定の同定面には使えない、と判断した。

(この「SVG では足りない」という壁は、姉妹プロジェクトの Loomit 側でも同時にぶつかっていた。)

## SVG ではなく DXF(ASTM) にたどり着いた

そこで、洋裁 CAD には SVG とは別に **DXF(AAMA / ASTM)** という受け渡し形式があると分かり、
Valentina が出せる DXF を実際に調べた。

近い順に絞っていった — plain な DXF は layer が非標準、AAMA は piece 名の TEXT が消えてしまって不採用、
そして **ASTM** は規格どおりのフルな layer 構成に piece 名の TEXT まで残っていて、これを採用した。
決め手は「ファイル固有の当て推量ではなく、**ASTM 標準に基づいて layer の意味を確定できる**」ことだった。

ASTM DXF では、BLOCK が detail 名、layer 15 の TEXT が piece 名、
そして **layer 14 の閉じた POLYLINE が縫い線(net)= Seamlint が測る対象**、layer 1 が裁断線。
測定エンジン(ルール判定・サンプリング・ベクトル計算)は入力形式に依存しないので、読み取り部(parser)を差し替えるだけでDXF に載った。
SVG は限定的な対応として残し、測定の主な入力は ASTM DXF に移った。

## 「layer 2 は notch だ」と思い込んで、訂正した

DXF を採り入れた初期、layer 2 に並ぶ POINT を見て「これは notch(合印)だろう」と読んだ。

これは間違いだった。
ASTM 標準と実測で否定された — layer 2 は**輪郭の定義ノード(turn points)**で、1 detail に 18〜38 点もある。一方 `.val` に実在する passmark(合印)はせいぜい 3 個ほど。
もしあの思い込みを放置していたら、実在しない合印を 150 個以上でっち上げていた。

これはまさに、いちばん怖い「静かに間違える」の一歩手前だった。
標準に照らして訂正できたのは、「ファイル固有の推測でなく標準を根拠にする」と決めていたおかげでもある。

## 長さだけでは、どの辺と縫うか決まらなかった

縫い線を**構造辺(structural edge)ごと**に測れるようにしたうえで、次は「この辺は相手のどの辺と縫うのか」を決める番だった。

長さの一致だけで探すと、候補が一つに絞れない。
前身頃と後ろ身頃は、脇の縫い目(outseam)も股ぐりの縫い目(inseam)も両方共有し得るからだ。
そこで**2 段構え**にした — まず長さで候補を出し、
次に **notch の数と位置の対応(署名)** で connector ごとに一意化する。
それでも決まらなければ、黙って推測せず、理由付きで保留する(`ambiguous` / `no-notch-match`)。

捨てた案もある。
「同じ座標のノードを共有していれば繋がっている」という共有ノード仮説は、分かりやすいが脆かった。
ノードの同一性ではなく notch 署名で裏を取る方に倒したのは、宣言された対応点という**人の意図**を根拠にしたかったからだ。

## 閾値は、記憶ではなく実データで決めた

「相対差が何 % までなら合格」といった閾値は、頭の中の相場観ではなく、実際の試作を測って決めた。

相対差 5% 以内(実際の outseam は 815 と 807 で 1.0%、hem や crotch は 10〜22% で落ちる)、
主要辺は 120mm 以上、notch 位置は 0.03(実際の前後差 0.01 未満に余裕を見て)。
全部、試作の観測から引いた数字だ。ここでも「記憶で測らない」という同じ姿勢が出ている。

短い縫い目を取りこぼさないよう、主要辺で足切りして候補が無ければ全辺で測り直す予備処理(fallback)も入れた。
一律のしきい値で切り捨てない、という判断そのものだ。

## サンプリングの誤差が、主張する許容誤差に迫っていた

測定の土台はサンプリング — 曲線を点に刻んで長さを測る。ここに、静かな落とし穴があった。

刻みを曲線の長さに関係なく固定していると、長い曲線ほど誤差が積もる。
その誤差が、合否の基準にしている 3mm の許容誤差に迫ってくる。
つまり「本当は同じ長さの縫い目」を、測定の粗さのせいで「ずれている」と誤検出しかねなかった。
定規の目盛りの荒さが、合否ラインに近づいている状態だ。

そこで、点の刻みを**曲線の長さに応じて細かくする**方式に変えた。
狙いは単純で、「主張する許容誤差より、測定そのものの誤差を明確に小さく保つ」こと。

(dart についても、先端の折り返しを畳んでから縫い閉じ後の長さで測るようにした。
実際のピースの角は口が広いので、意図した角を誤検出しない。)

## warning と error は、安全の境界線だった

診断の深刻度(severity)も、ただの色分けではなく安全の境界として設計した。

`warning` は「人間、見て」(exit 0 のまま)。`error` は「この検査は信用できない、あるいは実行できなかった」。
取り違えると、設計意図のズレで CI を止めてしまうか、検査できない geometry を素通しするか、どちらも下流の判断を誤らせる。

だから、角の折れ・長さ差・端点の隙間・つなぎ目の向きのような「設計意図のズレ」は `warning` から始め、`warning` だけでは CI を止めない。
検査の前提そのものが崩れるときだけ `error` にする。

## 辺の同一性を、外に漏らさない

境界の引き方でも、一度検討して捨てた案がいくつかある。

一つは、隣り合う辺を `edgeId` として契約に載せLoomit から名指しで渡してもらう案。
だが Loomit の実装を確認して撤回した。
Loomit の一貫した方針は「**辺そのものでなく名前(token)で指す — 辺はSeamlint が幾何から発見する**」で、辺の同一性を契約に漏らすとその方針が崩れる。
band の縫い目の契約は、辺でなく BLOCK(名前ラベル)ベースに設計し直した。

もう一つは、将来の Truer に辺の情報を渡すとき、Seamlint 内部の `structuralEdges` を直接ライブラリとして読み込ませる案(A2)。
これも却下した。それは公開契約([`library-api.md`](library-api.md))に無い内部実装で、結合すると境界が崩れる。
代わりに、別プロセス越しの呼び出しと、Seamlint 側の
診断の**拡張**で辺の住所を渡す(A1)に決めた。

どちらも根は同じで、「Seamlint は幾何を測って構造化診断で返すだけ、その内部や辺の同一性を外に晒さない」という狭さを守るためだ。

## false positive は、道具の価値を殺す

最後に、鳴らし方の哲学。

出荷している見本ファイル(fixture)の「意図した角」でwarning が鳴るなら、それは設計バグとして扱う。
裾角や衿先は、折れているのが正しい。
道具が「狼が来た」を繰り返すと、人はやがて全部のwarning を無視し始める。
だから閾値は、意図した geometry で鳴らないように較正する。

ルールを足すときは、「鳴るべき見本」と「鳴ってはいけない見本」の両方で証明する。
誤検知(false positive)を減らすことは、機能を足すことと同じくらい、この道具の価値に直結している。

## まだ途中にあるもの

Seamlint は、まだ測れる範囲のすべてを測れているわけではない。

- notch は ASTM でもまだ書き出されず、ギャザーやいせの範囲チェックにしか効いていない
  (主力の縫い目長・端点・つなぎ目の向きは layer 14 だけで動く)。
- SVG は限定的な対応として残っていて、単位なしや `viewBox` 無しの入力は「1 描画単位 = 1mm」
  前提のまま測る既知の穴がある。
- 見つけた問題を人の承認のぶんだけ実際に直す役は、将来の Truer に残っている。

それでも、何が測れて、何がまだ測れないのかを、以前よりはっきり言えるようになった。
この設計史は「完成した正解」の記録ではなく、静かに間違えないことを軸に、SVG から DXF へと測り方を引き直してきた過程の記録である。
